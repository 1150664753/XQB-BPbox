# 团队资源使用指南

适用版本：XQB-BPBox 1.2.6。

“团队资源”通过 GitHub 仓库共享角色、光锥、图片、音频、配置和 BP 结果。每位成员使用自己的 GitHub 账号授权，按需发布本地修改或获取远程更新。该功能不会自动把整台电脑的文件上传，也不会在索引缺失时清空本地资源。

## 1. 首次使用前准备

团队管理员需要准备：

- 一个用于存放团队资源的 GitHub 仓库，建议使用独立的私有仓库。
- 仓库所有者、仓库名和同步分支，例如 `my-team`、`team-resources`、`main`。这些是示例值，请替换为团队实际配置。
- 一个启用了 **Device Flow** 的 GitHub OAuth App，以及它的公开 **Client ID**。
- 成员的仓库访问权限：下载需要读取权限，发布和初始化还需要写入权限。组织授权策略、分支保护规则也可能限制写入。

管理员可以在 GitHub 的 **Settings → Developer settings → OAuth Apps** 创建 OAuth App，按页面要求填写信息，并启用 **Enable Device Flow**。创建步骤见 [GitHub 官方文档](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app)。向团队提供 Client ID 即可，BPbox 不需要填写 Client Secret；不要共享账号密码或个人令牌。

已有仓库应使用实际存在的分支。没有任何提交的全新空仓库可以通过后文的初始化流程创建同步分支。首次初始化或恢复丢失的索引前，建议备份本地数据目录和远程仓库。

## 2. 配置仓库并授权

1. 打开 BPbox 左侧的 **团队资源**。
2. 在“GitHub 仓库与个人授权”中填写：

   | 字段 | 填写内容 |
   | --- | --- |
   | 仓库所有者 | 仓库网址中的用户名或组织名 |
   | 私有仓库名 | 仓库名，不填完整网址，也不带 `.git` |
   | 分支 | 团队约定的同步分支 |
   | OAuth App Client ID | 管理员提供的、已启用 Device Flow 的 Client ID |

3. 点击 **保存设置**，再点击 **使用 GitHub 授权**。
4. 在自动打开的 GitHub 页面登录自己的账号，输入 BPbox 显示的验证码并完成授权。也可以打开 [GitHub 设备授权页](https://github.com/login/device) 输入验证码。
5. 等待 BPbox 显示授权成功，选择团队约定的 Profile，点击 **刷新差异**。

**授权成功只代表本机取得了登录凭据，不代表目标仓库可读写，也不代表远程索引存在。** 请继续查看“当前同步状态”和具体提示。

授权凭据由系统安全存储加密保存，仅用于本机；不会随团队资源上传。更换 OAuth App Client ID 后需要重新授权。**退出本机授权**会删除本机保存的凭据；需要撤销 GitHub 上的应用授权时，请到 GitHub 的应用设置中处理。

### Profile 与资源目录

默认映射为本地“星穹铁道”对应远程 `default`。默认 Profile 的资源保持在仓库的 `assets/`、`config/`、`results/` 中，下载后也按原分类目录和文件名保存。

自定义 Profile 需要由管理员配置数据目录下的 `config/team-profiles.json`，并让成员使用相同的映射。其他 Profile 的远程资源位于 `bpbox/profiles/<Profile ID>/` 下的对应分类目录。不要通过随意更换 Profile ID 来恢复丢失索引，这会被视为另一套资源。

## 3. 初始化远程索引

索引用于记录资源身份、属性、文件位置和内容摘要。没有有效索引时，BPbox 暂停正常对比、上传和下载；本地 BP 功能仍可使用。

以下情况可能需要初始化：

- 新建的空仓库没有任何提交。
- 仓库中只有 README 等文档，还没有使用过团队资源。
- 原来可以同步，但远程索引被误删，例如手动删除了所有非 Markdown 文件。

操作步骤：

1. 先确认仓库、分支和 Profile 正确，点击 **刷新差异**。
2. 只有程序确认索引不存在，且当前账号具有写入权限时，才会提供 **初始化远程索引** 按钮。
3. 点击按钮，核对本地对象数量、远程已有文件数量和风险提示。
4. 如果远程已有资源，先备份并人工核对，再勾选 **我已核对已有资源并确认上述风险**。
5. 点击 **确认初始化并发布本地资源**，等待校验和上传结束。
6. 完成后页面刷新，恢复资源对比、上传、下载和缺失资源恢复。

初始化使用**当前 Profile 的全部本地可共享对象**生成索引，不是只发布列表中勾选的几行。视频、缺失文件、外部路径和超过大小限制的文件按现有同步规则跳过；不可共享的属性或无效依赖可能阻止初始化，请按提示处理。

### 已有资源但索引丢失时

- 初始化只新增文件或复用内容完全相同的文件，**不会删除仓库中已有的其他文件**。
- 如果同一路径已有不同内容，初始化停止，不会覆盖。勾选风险确认也不代表允许覆盖。
- 仅存在于远程、没有对应本地对象的文件会保留，但不会自动加入新索引。
- 如果需要完整保留原有团队记录，优先从 Git 历史恢复正确的索引及其对应资源，再刷新差异。不要用不完整的本地数据直接代替原团队数据。
- 无法确认远程状态、权限不足或索引损坏时，程序不会开放初始化；先解决对应问题。

全新空仓库初始化时会先生成 `.bpbox/initializations/` 下的一份说明文件，再提交资源和索引。中途中断可能留下该说明文件；刷新后按提示重试即可，不代表索引已经创建完成。

## 4. 发布本地修改

1. 在角色、光锥、流程、展示设置等页面完成本地修改并保存。
2. 回到 **团队资源**，点击 **刷新差异**，切换到 **发布本地修改**。
3. 根据类型、状态或关键词筛选资源，查看新增、修改、删除和冲突项。
4. 打开资源详情，核对属性和文件；需要只发布部分文件时，选择对应字段。配置文件的内容与相关属性按依赖规则一并处理。
5. 使用单项 **上传**，或勾选资源后点击 **批量发布**。
6. 等待完成，再刷新确认剩余变更。

批量选择可能包含当前筛选下其他分页中的资源，操作前核对选中数量。发布前若发现远程已有新提交或本地内容已经变化，程序会要求重新刷新和核对，不会强制覆盖其他成员的提交。

## 5. 获取远程更新与恢复缺失文件

1. 点击 **刷新差异**，切换到 **获取远程更新**。
2. 查看详情，选择需要的对象或文件。
3. 点击单项 **下载** 或 **批量下载**。
4. 下载内容经摘要校验后写入原分类目录；没有选中的对象和字段保持原样。

如果资源记录仍在，但本地图片、音频等文件被误删，列表会显示 **本地缺失 / 可恢复**。选择需要的缺失项后，使用 **恢复** 或 **批量恢复**。即使远程没有新提交，也能从现有索引恢复缺失文件。

### 运行 BP 时下载

BP、展示窗口、预览或配音联动占用资源时，程序会显示占用原因。可以先下载并校验，文件暂存，稍后应用。

结束相应操作、关闭占用窗口后，回到团队资源点击 **应用待处理下载**。不再需要这批下载时，点击 **取消待应用下载**；取消暂存不会覆盖本地资源。

## 6. 理解差异与冲突

状态取决于当前选择的是“发布本地修改”还是“获取远程更新”，请结合详情中的本地和远程值判断。

| 状态 | 含义与处理 |
| --- | --- |
| 新增 | 该方向出现了另一端尚未收录的资源，核对后上传或下载。 |
| 修改 | 属性或文件内容发生变化，可以按字段选择。 |
| 删除 | 有效索引和同步基线表明发生了删除；确认是否需要传播该删除。 |
| 冲突 | 本地和远程均有变化，需要先选择冲突处理方式。 |
| 本地缺失 / 可恢复 | 索引仍记录文件，本地文件缺失，可选择恢复。 |
| 无变化 | 当前比较未发现需要同步的差异。 |

冲突详情可选择保留本地、采用远程或保留副本等界面提供的方式；不同对象可用的操作以界面为准。选择前查看属性差异和文件详情，尤其注意删除项。有效的远程删除可能删除对应本地记录；配置或结果文档的删除也可能移除本地文件。

**远程索引缺失不等于所有资源都被删除。** 缺失、损坏或读取失败时，程序保留本地资源和上次索引，不会据此生成批量删除本地资源的操作。

## 7. 哪些内容可以同步

| 内容 | 规则 |
| --- | --- |
| 角色、光锥资料 | 同步可共享属性及所选图片、音频等文件。 |
| BP、展示、音频等配置 | 同步受支持的 `config/` JSON 文档及其可共享资源引用。 |
| BP 结果 | 同步 `results/` 下受支持的 JSON 文档。 |
| 唱名视频、PV 等视频 | 不上传视频文件；配置中可能保留相对路径，需要各成员自行准备视频。 |
| 数据目录外的绝对路径 | 不直接上传；在详情中填写 `assets/` 下的分类路径，使用 **安全导入到本地分类目录**，再刷新。 |
| 本地不存在的文件 | 跳过并提示，不作为有效上传内容。 |
| 过大的文件 | 单文件上限为 95 MiB，超过限制时跳过并提示。 |
| 登录凭据及设备专属配置 | 不作为团队共享内容；令牌、密码等敏感字段会被过滤或拒绝。 |

团队资源不是整个文件夹的镜像工具。未被对象或受支持配置引用的任意文件，不会仅因为放进目录就自动上传。发布前仍应核对内容，避免把私人资料写进普通名称、备注或其他可共享字段。

## 8. 查看进度和处理等待

同步进度按阶段显示，包括扫描、准备上传、生成配置、初始化校验和文件传输。

- 总数已知时显示当前阶段的总数、已完成数和百分比；“已完成”包含已跳过的文件。
- 扫描尚未确定总数时显示活动进度条和已处理数量。
- “当前文件”表示正在处理的文件；网络活动信息会显示请求、等待秒数、超时或重试状态。
- 切换阶段时进度计数会重新计算，因此百分比可能回到较小值。
- 需要中止时使用 **取消同步**。最终提交确认阶段可能暂时不能取消，此时等待结果，避免重复点击初始化或发布。

大量资源首次初始化需要扫描、计算摘要并检查远程路径，耗时会受文件数量和网络影响。1.2.6 会复用同一次操作中已校验的远程目录树，避免为每个缺失文件重复请求目录。若长时间停留在同一文件，先查看网络活动和超时提示；失败后处理具体错误，再刷新重试。

## 9. 常见状态与排查

| 提示 | 建议操作 |
| --- | --- |
| 空仓库，待初始化 | 有写入权限的管理员确认本地资源后手动初始化。 |
| 仓库待初始化 / 远程索引缺失 | 核对仓库、分支和 Profile；已有团队数据时优先恢复历史索引，或按风险提示初始化。没有历史记录时，程序不能断言索引一定曾被删除。 |
| 索引格式损坏 | 从 Git 历史恢复有效版本并核对对应资源；不会自动用新索引覆盖。 |
| 网络异常 | 检查 GitHub 连通性和网络环境，稍后刷新；不要通过初始化处理网络问题。 |
| 权限不足 | 核对授权账号、仓库成员权限、组织应用授权和分支保护规则，必要时重新授权。 |
| 仓库或分支无法访问 | 核对所有者、仓库名及分支。已有仓库中的分支不存在，不等于仓库为空。 |
| GitHub 请求限流 | 按提示等待后重试，避免连续重复刷新。 |
| 两个位置同时存在索引 | 管理员备份并核对哪份索引为准，保留唯一权威索引后再同步。 |
| 初始化检测到同路径不同内容 | 对比并备份本地与远程文件，恢复正确索引或人工统一内容；程序不会强行覆盖。 |

## 10. 索引位置与团队维护

新初始化的索引位于独立元数据目录：

```text
.bpbox/profiles/<Profile ID>/manifest.json
```

旧仓库的索引可能仍在：

```text
bpbox/profiles/<Profile ID>/manifest.json
```

新版兼容旧位置，并继续在原位置更新，不自动移动既有资源。新位置和旧位置不能同时保留两份有效索引。

清理普通素材时，请只操作明确的资源文件，并保留 `.bpbox/`。索引本身是 JSON，**“删除所有非 Markdown 文件”仍会把它删除**，独立目录并不能防止这种全仓库清理操作。

团队使用新索引路径前，应统一升级到支持该路径的版本，避免旧客户端再次初始化。数据目录中的 `.team-sync/` 保存本地基线、缓存及暂存事务，不是需要分享的资源，也不应作为排错的第一步随意删除。

推荐日常流程：管理员首次初始化 → 成员授权并下载 → 各自修改和保存 → 刷新差异 → 处理冲突 → 发布所需资源 → 其他成员获取更新。

实现细节和兼容规则见 [团队资源索引与初始化](./TEAM_RESOURCE_INDEX.md)；其他功能见 [操作指南](../操作指南.md)。
